## 2. コンセプト

### キャッチコピー
「和紅茶とお野菜と富山湾の幸」

### 理念
近年、色んな分野で新しいものが次々と生まれ、無意識にそれらを追っていくうちに人はとてもせわしなく日々を過ごしている。食という生きる上で一番重要な部分をコンビニ弁当やファストフードなどによって疎かにしていることから抜け出せずにいる。

そんな慌ただしく過ごす日々の中で【食】という生きてゆくうえで欠かすことができない部分を通じて、生き物としての原点回帰をし、様々な事柄について本質的なアプローチをしていくカルチャーを発信していく。

### 食材へのこだわり
- **不使用**: 小麦、乳製品、卵、添加物
- **魚**: 必ず富山県産の魚を使用
- **野菜**: 富山県の無農薬栽培農家と契約
- **米**: 富山県産を使用
- **食後**: 豆花と和紅茶を提供

### 料理について
- 毎週、旬の食材でメニューを構成
- **苦手食材・アレルギー対応は不可**
- 魚の火入れ等は対応可能（備考欄に記載）

### お席について
- 原則カウンター席のみ
- テーブル席希望の場合は事前相談（妊婦・お年寄りの方向け）
- 冬場はブランケット貸し出しあり

### 駐車場について
- 専用駐車場なし
- 最寄り: NPC24H高岡駅南第2パーキング（店舗裏側）
- **パーキングチケット持参で1台につき100円引き**
- 隣接店舗「ゆいまーる」の駐車場は利用不可

## 4. 予約ルール

### 予約可能条件
- 予約可能期間: 前日〜2週間先まで
- 予約可能人数: 1〜7名
- 当日予約: 不可（Instagram DMで直接連絡）
- 8名以上の団体: 不可（Instagram DMで直接連絡）
- 2週間以上先: 不可（Instagram DMで直接連絡）

### 予約フロー
1. 顧客が予約を申請
2. システムが顧客へ受付確認メールを送信する
3. オーナーが内容を確認
4. オーナーが承認または拒否
5. 顧客に結果がメールで通知される（承認／拒否）

### 予約の変更・キャンセル
- システム上での変更・キャンセルは不可
- Instagram DMでオーナーに直接連絡する必要がある
- **キャンセルは前日までに連絡必須**
- **当日キャンセルは100%のキャンセル料が発生**
- オーナーが連絡を受けたあと、管理画面でステータスを手動更新する（キャンセル用の顧客向けシステムメールは送らない）

### 備考欄の用途
- 魚の火入れ希望
- テーブル席希望（妊婦・お年寄りの方）
- その他連絡事項
- ※アレルギー・苦手食材の対応は不可

### 朝営業について
- 日曜の8:30〜の朝営業は予約不可
- 来店順での対応
- 祝日は朝営業なし（11:30〜の通常営業）。祝日が日曜に重なる場合も朝営業なしで、店舗定例の合成はそのように扱う（朝営業をしたい場合は `daily_schedules` で `morning` を登録して上書きする）
- 祝日の判定は内閣府「国民の祝日」CSV を同梱したデータに基づく（年 1 回更新。[`holidays.md`](./holidays.md)）

## 5. 用語集

| 用語 | 説明 |
|------|------|
| 予約申請 | 顧客が予約をリクエストすること。この時点では確定していない |
| 承認 | オーナーが予約申請を受け入れること |
| 拒否 | オーナーが予約申請を断ること |
| 無断キャンセル（no_show） | 予約したが連絡なく来店しなかったこと |
| 当日キャンセル | 来店日当日にキャンセルすること。キャンセル料100%が発生 |
| 提供可能数 | その日に提供できる食事の最大数 |
| 残り食数 | 提供可能数から予約済み（pending + approved）の合計人数を引いた数（NOTE: ローンチ前に要確認 pending を reserved に含める仮方針） |
| テーブル席 | 通常はカウンター席だが、妊婦・お年寄り向けに相談可能 |
| 魚の火入れ | 魚の焼き加減の調整。対応可能なリクエストの例 |

## 6. スケジュールタイプ

| タイプ | 説明 | 予約 | デフォルト営業時間 |
|--------|------|------|-------------------|
| normal | 通常営業（月火水土祝） | 可 | 11:30-15:00 (LO 13:30) |
| morning | 朝営業（日曜） | 可 | 8:30-15:00 (LO 13:30) |
| event | 店内イベント等（和紅茶をしばく会等） | 可（注意書き表示） | 省略時は暦日別デフォルト（祝日でない日曜=朝、それ以外=通常） |
| external_event | 外部イベント（WINE LAB 等で開催・店舗休業） | 不可（イベント情報表示） | なし（時刻は保存しない） |
| special_menu | 特別メニュー（リゾットランチ等） | 可（注意書き表示） | 通常と同じ |
| closed | 臨時休業 | 不可 | なし（時刻は保存しない） |

**注意:**
- 休業に相当する日かどうかは、**保存された `daily_schedules` を正**とし、行が無い日はドメイン既定（上記の定例カレンダー等）で解決する。木・金を休みにするのはその既定の一部であり、曜日だけをハードコードして DB と二重管理しない。**行がある日は定例よりオーナー登録が優先**される（例: 定例木曜でも `event` 登録すれば営業日になる）。
- 行が無い日の既定は **祝日 → 曜日** の順で決める。祝日は曜日にかかわらず `normal`（木・金の祝日は営業日、日曜の祝日は朝営業なし）。それ以外は木・金 `closed`、日曜 `morning`、月火水土 `normal`。祝日データは同梱の内閣府 CSV（[`holidays.md`](./holidays.md)）で、同梱データに無い年は「祝日なし」として曜日だけで解決する。
- 店内イベント日・特別メニュー日は予約可能だが、顧客にはイベント情報が表示される
- 外部イベント日は店舗休業（予約不可）だが、顧客カレンダーでは「休」+ イベント名を表示する
- **`event` 登録時** — `event_name` は必須、`event_description` は任意。営業時刻を省略した場合はその日の暦日に応じた店舗デフォルトを適用（祝日でない日曜=朝営業、それ以外=通常営業。祝日は日曜と重なっても朝営業なし）。朝営業の時刻にしたい場合は時刻を明示する
- **`external_event` 登録時** — `event_name` は必須、`event_description` は任意。`capacity` は 0 固定。営業時刻は保存しない
